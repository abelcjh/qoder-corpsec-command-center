# Credence Submission Boundary

Use this rule whenever editing submission packaging, social/video copy, deploy notes, AI claims, or integration claims.

## Manual external actions only

Credence must not automatically:

- post LinkedIn/X/social content;
- submit the Alibaba Cloud/Qoder form;
- send email, WhatsApp, SMS, or client messages;
- mutate legal/compliance status in a real system;
- spend paid cloud resources or rotate/expose secrets.

The app may show paste-ready drafts, fixture-safe proof rows, seeded credentials, and manual checklists.

## Rule-clean Qoder story

- Say Qoder was central to the spec-driven build and workflow evidence.
- Keep `Spec.md`, preserved Qoder prompts, `QODER_BUILD_LEDGER.md`, `PROOF_LEDGER.md`, `AGENTS.md`, `.qoder/rules/`, and `npm run build && npm run verify` visible as the reusable workflow proof.
- Disclose Ralph/Hermes/Cloudflare/GitHub patches as supporting reliability/packaging work, not hidden Qoder traces.
- Do not claim private Qoder canvas screenshots, Qoder Security L2/L3 scans, qoder-action CI, Gmail/WhatsApp ingestion, MBRS filing, MCP/AP2 integration, or legal-grade cryptography unless artifact-backed.

## Final recording spine

Keep the 2–3 minute route tight:

`problem/Qoder → admin client DB → rule/scheduled queue → reviewer-safe proof row → governed Agnes AI → Submission Pack close`.

If the live app or Agnes stalls, use saved smoke receipt plus `npm run build && npm run verify`; do not improvise external sends or unsupported claims.
